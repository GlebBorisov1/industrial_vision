# 📄 Model Cards

Документ описывает все модели, используемые в проекте, их назначение, метрики и ограничения.

## 1. YOLOv8n (COCO) — Baseline

### Назначение
Детекция людей (`person`) и транспорта (`car`, `truck`, `bus`, `motorcycle`). Используется на Этапе 3 как baseline и в конвейере контроля СИЗ/зоны как источник детекций людей.

### Архитектура и обучение
- **Архитектура:** YOLOv8n (Ultralytics).
- **Checkpoint:** `yolov8n.pt`, предобучен на COCO (80 классов).
- **Fine-tuning:** **не выполнялся** — COCO содержит класс `person` с хорошим качеством.

### Производительность (CPU Intel Core i5-13420H)
- **PyTorch:** ~78 мс/кадр.
- **OpenVINO FP16 (`imgsz=480`):** ~35 мс/кадр (используется в проекте).
- **Размер:** ~6.1 МБ.

### Ограничения
- Не детектирует СИЗ, дым, огонь, разлив (другие задачи — другие модели).
- Может ошибаться на сильно перекрытых людях (стандартная проблема COCO-моделей).

## 2. YOLO26n (fine-tuned) — Контроль СИЗ

### Назначение
Детекция средств индивидуальной защиты: `helmet`, `head` (голова без каски), `vest`.

### Архитектура и обучение
- **Архитектура:** YOLO26n (Ultralytics).
- **Исходный checkpoint:** `yolo26n.pt` (COCO).
- **Данные:** `jhboyo/ppe-dataset` (см. Dataset Card).
- **Параметры:** 50 эпох, `imgsz=640`, `batch=16`, `patience=10`.
- **Среда обучения:** Google Colab, GPU Tesla T4.

### Метрики (test split — 2751 изображение, 10 862 объекта)

**PyTorch, `imgsz=640`:**

| Метрика | Значение |
|---|---|
| Precision | 0.9137 |
| Recall | 0.8937 |
| mAP@0.5 | 0.9492 |
| mAP@0.5:0.95 | 0.6867 |
| Inference (CPU) | 78.3 мс |

**OpenVINO FP16, `imgsz=480` (production-конфигурация):**

| Метрика | Значение | Δ |
|---|---|---|
| Precision | 0.9080 | −0.6 п.п. |
| Recall | 0.8769 | −1.7 п.п. |
| mAP@0.5 | 0.9353 | −1.4 п.п. |
| mAP@0.5:0.95 | 0.6670 | −2.0 п.п. |
| **Inference (CPU)** | **35.6 мс** | **−54%** |

**Подбор порога confidence:**

| conf | Precision | Recall | F1 |
|---|---|---|---|
| 0.30 | 0.9137 | 0.8937 | 0.9036 |
| **0.50 (рабочий)** | 0.9406 | 0.8631 | 0.9002 |
| 0.70 | 0.9753 | 0.7406 | 0.8419 |

**Обоснование порога 0.50:** F1 практически максимален (разница с 0.30 — 0.3%, в пределах шума), но Precision выше — меньше ложных тревог. Порог 0.70 отклонён из-за падения Recall до 0.74.

### Ограничения
- Не детектирует людей целиком (только `head`, `helmet`, `vest`).
- Обучена на преимущественно дневных сценах с хорошим освещением.
- Возможны ошибки при сильном перекрытии и на мелких объектах (`< 120 px` по высоте — не анализируются).
- Класс `head` (голова без каски) иногда путается с `helmet` при плохом качестве кадра.

## 3. fire-smoke YOLOv8n — Детекция дыма и огня

### Назначение
Детекция визуальных признаков дыма (`smoke`) и огня (`fire`) для формирования событий безопасности.

### Архитектура и источник
- **Архитектура:** YOLOv8n.
- **Источник:** [rabahdev/fire-smoke-yolov8n](https://huggingface.co/rabahdev/fire-smoke-yolov8n).
- **Классы:** `{0: 'smoke', 1: 'fire'}`.
- **Fine-tuning:** **не выполнялся** — использована готовая модель.

### Пороги (откалиброваны на тестовом видео)
| Параметр | Значение | Обоснование |
|---|---|---|
| `fire_confidence` | 0.30 | Модель редко превышает 0.35 на fire в реальных сценах; при 0.4 fire не детектируется |
| `smoke_confidence` | 0.35 | Smoke уверенно детектируется от 0.40+; 0.35 даёт запас на ранние стадии |

### Постобработка
Перед генерацией события применяется фильтрация hard negatives (`src/analytics/smoke_fire_filter.py`):
- `min_area_px=2000` — отсекает мелкие пятна.
- `max_aspect_ratio=5.0` — отсекает вытянутые блики (сварка, фары).

### Latency (temporal confirmation)
| Событие | N/M | Latency | Цель (методичка) |
|---|---|---|---|
| `smoke_detected` | 3/5 | 0.34 с | ≤ 5 с ✅ |
| `fire_detected` | 2/3 | 0.64 с | ≤ 5 с ✅ |

### Ограничения
- Модель обучена на открытом датасете (вероятно, D-Fire или аналог) — может быть чувствительна к типу сцены.
- Hard negative «сварка» требует проверки на реальном видео (в тестовом видео отсутствовала).
- Пар (чайник) корректно игнорируется (проверено).
- Не детектирует **маленькие** очаги (фильтр `min_area_px=2000`).

## 4. spill_leak_detection_nano — Сегментация разлива

### Назначение
Сегментация разливов нефтепродуктов (`oil`) на промышленных сценах. Исследовательский сценарий по методичке (раздел 13.1).

### Архитектура и источник
- **Архитектура:** YOLO-seg.
- **Источник:** [kareem1232/spill_leak_detection_nano](https://huggingface.co/kareem1232/spill_leak_detection_nano).
- **Классы:** `{0: 'oil'}` — только нефтепродукты.
- **Веса:** `weights/best.pt` (~19.2 МБ).
- **Fine-tuning:** **не выполнялся** — использована готовая модель.

### Производительность (CPU Intel Core i5-13420H)
- **FPS:** ~7–10

### Параметры интеграции
| Параметр | Значение |
|---|---|
| `confidence` | 0.40 |
| `min_area_px` | 3000 (площадь маски, а не bbox) |
| `iou` | 0.5 (NMS) |

### Ограничения
- Только нефтепродукты (`oil`). Для воды, химикатов, красных жидкостей требуется дообучение.
- Не проверялась на hard negatives «мокрый бетон», «тени» — потенциальные FP требуют валидации.
- Площадь маски используется для фильтрации мелких брызг, но не калибрована под «0,5 м²» из методички (нужна привязка к перспективе).

## 5. Сравнение моделей

| Модель | Задача | Размер | CPU inference | Классы | Статус |
|---|---|---|---|---|---|
| YOLOv8n (COCO) | Детекция людей/транспорта | ~6 МБ | ~35 мс (OpenVINO) | 80 (COCO) | ✅ Production |
| YOLO26n (PPE) | Контроль СИЗ | ~5 МБ | ~35 мс (OpenVINO) | 3 | ✅ Production |
| fire-smoke YOLOv8n | Дым и огонь | ~6 МБ | ~40–50 мс | 2 | ✅ Production |
| spill_leak_detection_nano | Сегментация разлива | ~19.2 МБ | ~200–300 мс | 1 (`oil`) | ✅ Исследовательский |

**Архитектурные решения:**
- **Baseline + PPE** разделены: baseline даёт `person` с Track ID, PPE — каску/жилет. Это компромисс между точностью (модель на PPE не знает `person`) и простотой интеграции.
- **fire-smoke** — отдельная модель, т.к. признаки визуально не пересекаются с другими задачами.
- **spill** — сегментация предпочтительнее детекции (границы пятна важнее bbox). Эвристика оставлена как fallback.
